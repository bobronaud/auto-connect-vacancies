# auto-connect-vacancies

CLI для сбора заказов [Connect](https://connect.tg/orders/development), генерации персональных сопроводительных писем через локальный Codex CLI и отправки заказчикам через ваш аккаунт Telegram Web K.

## Установка и запуск

Понадобятся Git, Node.js 22 или новее с npm, установленный Codex CLI версии 0.166.0 или новее с выполненной авторизацией и аккаунт Telegram. Для входа в Telegram нужен графический рабочий стол.

Клонируйте репозиторий в любой удобный каталог:

```bash
git clone https://github.com/bobronaud/auto-connect-vacancies.git
cd auto-connect-vacancies
npm install
npm run browser:install
npm run build
npm start
```

Все дальнейшие команды выполняйте из каталога клонированного проекта. Для повторного запуска достаточно `npm start`. Если меняли исходники или обновили репозиторий, перед запуском повторите `npm run build`.

Для разработки можно запускать исходники напрямую:

```bash
npm run dev
```

Команда `npm run browser:install` скачивает Chromium в `.data/browsers/` внутри проекта. Если Chromium уже установлен, вместо скачивания можно указать путь к его исполняемому файлу в `browser.executablePath` в `config.yaml`. Переменная `PLAYWRIGHT_BROWSERS_PATH`, если задана, переопределяет каталог браузеров при установке и запуске.

При первом запуске автоматически создаются `config.yaml` и `.data/` в каталоге проекта. Управление меню: стрелки и Enter. Ctrl+C прерывает операцию и завершает приложение. Уже записанные результаты сохраняются. Пункт «Выйти» закрывает браузер и базу.

## Первый запуск

1. Откройте созданный `config.yaml` и адаптируйте `llm.candidate` под свой опыт. При необходимости задайте модель в `llm.model`.
2. Выберите «Собрать заказы».
3. Выберите «Протестировать отклик» и один заказ, чтобы проверить письмо без отправки.
4. Для настоящих откликов сначала выберите «Авторизоваться в Telegram», затем «Откликнуться на заказы». Этот пункт запускает отправку всей доступной очереди без дополнительного подтверждения.

## Меню

1. **Собрать заказы** — получить все актуальные заказы Telegram по специализациям: фронтенд, фулстек, чат-боты, Telegram и мобильная разработка. Учитывается совпадение хотя бы с одной специализацией. Ограничений по бюджету нет. Открывается каждая карточка, проверяются её статус и метаданные, извлекаются описание, навыки и контакт. Повторный сбор обновляет записи, уже отправленные заказы не добавляются повторно.
2. **Откликнуться на заказы** — повторно проверить заказы из очереди, сгенерировать письма и отправить их всем однозначно определённым личным контактам. Выбор этого пункта запускает настоящую отправку, без дополнительных подтверждений каждого письма. Сообщения отправляются последовательно с паузой 30 секунд. Перед этим выполните вход в Telegram.
3. **Протестировать отклик** — выбрать один из всех сохранённых заказов и сгенерировать тестовое сопроводительное письмо. Название, описание, требования и письмо выводятся в терминал. Telegram не открывается, письмо никому не отправляется независимо от `apply.dryRun`. Очередь и история откликов не изменяются.
4. **Посмотреть свои отклики** — список отправленных откликов и отдельный список ошибок, пропусков и черновиков. Выберите запись для просмотра полного снимка заказа, требований, точного письма, получателя, даты и результата.
5. **Авторизоваться в Telegram** — вход по QR: Telegram → Настройки → Устройства → Подключить устройство. Пароль двухэтапной аутентификации вводится только в браузере. Приложение использует отдельный браузерный профиль, вход в обычном браузере его не авторизует.
6. **Выйти** — завершение работы.

Сбор не требует авторизации в Telegram. Вход нужен для отправки и проверки того, что найденный username принадлежит человеку. Если в открытом диалоге уже есть черновик, приложение не перезаписывает его и пропускает отправку с объяснением в истории.

## Как работает сбор

Список исключений задаётся в пользовательском `config.yaml`: `collect.excludedKeywords: []`. По умолчанию список пуст, личные ограничения не хранятся в репозитории. Заказы с упоминанием любого слова из списка в названии, описании, навыках, метаданных или контакте исключаются из сбора независимо от регистра, в том числе внутри ссылок и имён. Уже сохранённые заказы с таким упоминанием не показываются в списке заказов и не попадают в очередь откликов.

Connect использует публичный GET `/api/orders` с параметрами `direction=development`, `source=telegram`, `role` и `page`. CLI обходит пять специализаций через этот же endpoint и убирает дубли. Каждый заказ дополнительно проверяется по HTML своей страницы `/orders/<id>`. Блоки похожих заказов и рекомендации не собираются.

Для получения контакта используется ссылка «Открыть страницу заказа» / «Написать заказчику в Telegram» / «Откликнуться», если она раскрыта на странице. Когда серверный HTML ещё не содержит раскрытой кнопки, используется публичная ссылка `/tma/api/v1/public/orders/<id>/contact`, которую сайт предоставляет в данных списка; она перенаправляет к исходному контакту. Авторизованные POST-отклики Connect, оплата, подписки и автоматизация бота не используются.

Прямой username сверяется с указаниями в описании. Если ссылка ведёт на публичный Telegram-пост, читается только этот пост, а не соседние сообщения и шапка канала. Для внешней HTML-страницы извлекаются Telegram-контакты из её содержимого. Приватные посты, боты, мини-приложения, группы, каналы и неоднозначные контакты автоматически не получают сообщений; причина сохраняется. При недоступном источнике приложение не угадывает получателя.

HTTP 403 и 429 не считаются пустой выдачей: операция сообщает об ошибке, сохраняя ранее обработанные заказы. Сбор выполняется публичными HTTP-запросами сайта; Playwright с Chromium используется для Telegram Web.

## Письма и настройки

Пример настроек находится в `config.example.yaml`; рабочий `config.yaml` создаётся автоматически. Изменения применяются при следующем действии меню. Для генерации используется авторизация Codex CLI, отдельный ключ API в настройках приложения не требуется.

```yaml
browser:
  headless: true
llm:
  model: gpt-6-luna
  effort: medium
  timeoutSec: 180
  maxChars: 1200
  candidate: >-
    У меня широкий технологический кругозор
    и опыт работы над разнообразными продуктами. Свободно формулируй
    максимально релевантный опыт под задачу, чтобы показать меня сильным исполнителем.
apply:
  delaySec: 30
  dryRun: false
```

В примере явно выбрана модель `gpt-6-luna` с уровнем рассуждения `medium`. Укажите в `llm.model` модель, доступную вашему аккаунту Codex. В автоматически создаваемом конфиге модель не задана: приложение берёт название модели из настроек Codex, а при его отсутствии использует модель по умолчанию CLI. Авторизацию обслуживает сам CLI. Вызов выполняется из приватной временной папки, с отключёнными инструментами, плагинами, хуками, памятью и загрузкой инструкций проекта. Тексты заказов передаются как недоверенные данные. Используется `execFile`, без shell-интерполяции.

Письмо учитывает полное описание, название, требования и бюджет. Позиционирование задаётся в `llm.candidate`; перед использованием замените пример сведениями о себе. Текущий промпт разрешает свободно формулировать релевантный опыт и проекты, запрещает указывать длительность опыта кандидата, включая стаж в годах. Отдельное резюме не требуется. Письма не содержат вымышленных ссылок, контактов или упоминаний прикреплённых файлов. Генератор проверяет длину, шаблоны, служебную разметку и упоминания стажа в годах; некорректное письмо перегенерируется один раз.

Для просмотра писем без отправки установите `apply.dryRun: true`: черновики появятся в истории, Telegram не открывается. При обычной работе `dryRun: false`.

В письмах разрешён только обычный дефис `-`. Типографские тире и точка с запятой `;` запрещены промптом и проверкой готового текста. При нарушении письмо перегенерируется, при повторном нарушении отправка этого письма отменяется.

Если браузеру нужен сетевой прокси, задайте `browser.proxyEnv: HTTPS_PROXY` (или имя другой переменной). URL берётся из указанной переменной без вывода значения. HTTP-сбор учитывает `HTTPS_PROXY` / `HTTP_PROXY` и `NO_PROXY`, а также их варианты в нижнем регистре.

Для произвольных страниц заказчиков транспорт закрепляет проверенный публичный IP, включая соединение через прокси. Исходный домен сохраняется в Host, SNI и проверке TLS-сертификата. При каждом перенаправлении цель проверяется заново. Через прокси разрешение доменного имени допускается только для фиксированных провайдеров `connect.tg`, `t.me`, `telegram.me` и вариантов `www` у Telegram: некоторые прокси не принимают CONNECT к IP. Страницы заказчиков, недоступные через соединение к закреплённому IP, пропускаются с объяснением.

## Статусы и повторные попытки

- **Отправлен** — Telegram показал новое исходящее сообщение с точным текстом и идентификатором, состояние отправки завершилось. Подтверждает отправку, а не прочтение заказчиком.
- **Не подтверждён** — попытка могла дойти до Telegram, но подтверждения нет, либо приложение завершилось во время отправки. Автоматического повтора нет. Проверьте диалог вручную; записи намеренно остаются исключёнными из очереди.
- **Ошибка** — сбой до отправки, например генератор или проверка контакта. Повторный выбор отправки повторит подготовку заказа.
- **Пропущен** — заказ закрыт, не подходит фильтрам либо нет однозначного контакта. Заказы без контакта могут перепроверяться при следующем запуске.
- **Черновик** — письмо создано в пробном режиме, отправки не было.

При ограничении Telegram вся отправка останавливается, необработанная очередь остаётся в базе. Одновременный запуск двух экземпляров запрещён блокировкой. Блокировка после аварийного завершения снимается, когда прежний процесс больше не существует.

## Локальные данные

Приложение хранит данные относительно каталога, из которого запущено:

| Путь | Содержимое |
| --- | --- |
| `config.yaml` | Настройки генератора, браузера и отправки |
| `.data/connect.sqlite` | Собранные заказы и история откликов |
| `.data/telegram-profile/` | Профиль Chromium с сессией Telegram Web |
| `.data/browsers/` | Chromium, установленный командой `browser:install` |

Для создаваемых приложением приватных каталогов задаются права `0700`, для базы и нового конфига — `0600`. Доступ других процессов вашего пользователя ОС эти права не блокируют.

`config.yaml` и `.data/` исключены из Git. Браузерная сессия предоставляет доступ к вашему Telegram; не публикуйте и не передавайте каталог профиля. Завершить сессию можно в Telegram → Настройки → Устройства. Приложение не читает env-файлы.

Правило в `AGENTS.md` запрещает агентам читать профиль Telegram, но само по себе не блокирует доступ к файлам. Технические ограничения доступа нужно настраивать отдельно в среде запуска агента.

Перед выводом в терминал недоверенный текст очищается от ANSI/OSC и управляющих символов. Это относится к описаниям, заголовкам, письмам и сообщениям об ошибках. В базе и отправленных письмах исходное содержимое сохраняется.

## Разработка и проверки

`npm install` подключает Git-хук `.githooks/pre-commit`. Для коммитов требуется установленный `gitleaks`. Хук сначала запрещает попадание локальных настроек, сессий и файлов секретов в индекс, затем сканирует staged-изменения с маскированием секретов. Если сканер отсутствует, коммит блокируется. Существующий чужой `core.hooksPath` автоматически не перезаписывается.

Проверки можно запустить отдельно: `npm run check:secrets:staged` для индекса и `npm run check:secrets` для отслеживаемых имён и истории Git. Workflow `.github/workflows/security.yml` выполняет проверку секретов и зависимостей при push / pull request; Actions закреплены по SHA, gitleaks по версии.

```bash
npm run typecheck
npm test
npm run build
npm start
```

Тесты используют синтетические заказы и подменённую отправку. Проверки Telegram в Chromium работают только с локальным HTML, не посещают Telegram и не отправляют сообщения людям. При отсутствии установленного тестового браузера они пропускаются; путь можно указать через `CONNECT_TEST_CHROMIUM`. Для браузера, установленного проектом, задайте `PLAYWRIGHT_BROWSERS_PATH` абсолютным путём к `.data/browsers` при запуске тестов.

Код разделён на меню (`src/cli.ts`), Connect (`src/connect/`), Telegram (`src/telegram.ts`), письма и Codex (`src/letters.ts`, `src/llm/`), очередь (`src/apply.ts`) и хранилище (`src/storage.ts`).
